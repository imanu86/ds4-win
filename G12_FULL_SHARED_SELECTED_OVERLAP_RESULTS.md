# G12 full shared/selected overlap

Date: 2026-07-13
Branch: `port/register-mmap-0050`
Parent: `20ca961` (`experiment: measure shared compute selected-load overlap`)

## Question

G11 overlapped only shared gate/up/SwiGLU with selected-expert file reads and
regressed the coding workload. Can including standalone shared-down provide enough
independent GPU work to hide the serial selected-expert transport?

The full experiment is opt-in:

```text
DS4_CUDA_MOE_OVERLAP_SHARED_FULL=1
DS4_METAL_DISABLE_SHARED_DOWN_HC_FUSION=1
```

## Controlled design

Three same-binary arms separate the overlap effect from the cost of disabling the
existing shared-down/HC fusion:

| Arm | Shared-down | Ordering |
|---|---|---|
| A | default fused | routed, then fused shared-down/HC |
| B | standalone | routed, then standalone shared-down |
| C | standalone | shared gate/up/down queued, selected pread/H2D, then routed |

The causal overlap comparison is C versus B. A is the production reference.

For C, selected IDs are read after the router, shared gate/up/SwiGLU and standalone
shared-down are queued on stream 0, and the existing selected loader performs serial
Windows reads and pinned H2D work while those kernels execute. The existing upload
sync remains. Routed kernels are subsequently queued on stream 0, preserving the
original data dependencies. Shared-down is not launched a second time.

Batch/prefill, router selection, expert bytes, arithmetic kernels, sampling, and the
default path are unchanged. The backend emits a distinct one-shot marker when the
full prepared state is actually consumed; the harness records requested and observed
state separately.

## Safety

One mechanism-only run per standalone arm confirmed identical generated bytes and an
observed full-overlap marker. These `n=1` runs are not performance evidence.

## Coding A/B/C

Prompt:

```text
Create a complete single-file HTML landing page for a cyberpunk AI programming shop. Include CSS, navigation, hero, request form, and a JavaScript confirmation popup. Return only the HTML document.
```

The same source, executable, and launch parameters were used with 64 requested
tokens, one discarded warmup, and `n=3` measured repeats.

| Arm | Mean t/s | Median t/s | Min-max | Delta vs B | Delta vs A | Output SHA |
|---|---:|---:|---:|---:|---:|---|
| A default fused | 1.425970 | 1.421220 | 1.415454-1.441237 | +1.2% | reference | `fd6c4522...` |
| B standalone | 1.408884 | 1.428039 | 1.340512-1.458100 | reference | -1.2% | `fd6c4522...` |
| C full overlap | 1.413148 | 1.412866 | 1.396402-1.430176 | +0.3% | -0.9% | `fd6c4522...` |

The B mean is pulled down by its first repeat; its median exceeds C. The intervals
overlap. G12 therefore does not support a positive coding-performance claim.

## Verdict

Full shared overlap is rejected as a production default. It gives a short-prompt
smoke improvement, but on the coding workload its causal C/B effect is effectively
neutral and it remains slower than the fused production path.

The result also narrows the next target: there is not enough independent shared
compute per layer to hide selected transport. Further progress should attack the
serial `pread`/staging path itself or predict and prefetch a later layer/token early
enough to overlap with substantial unrelated compute. PocketMoE's useful direction
here is semantic/layer-local prefetch, not its global LRU cache. QD2/QD4 and resident
expert caches remain rejected by G8-G10.
